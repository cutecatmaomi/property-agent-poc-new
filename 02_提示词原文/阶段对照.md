# 提示词与阶段对照

以下原文取自当前 Golden Questions 源码。文件保留原有空白、换行和内容。编号是本表的对照顺序，可映射到 Enact 现有技能阶段。

| 逻辑阶段 | 原系统实现 | 原文 |
|---|---|---|
| 前置规则 | 本地函数 `classify_message` 和 `workflow.guard` | 见源码 |
| 意图识别与报修槽位 | 一次 `plan_property_turn` 输出 route、tasks、repair、missing_slot、条件、用户原话引证 | `语义规划基础_SYSTEM_PROMPT.txt` |
| 同次规划中的自然回复 | 可选 `inline_reply` 与规划结果一起返回，仍走后台事实校验 | `同次自然回复_INLINE_PROMPT.txt` |
| 知识检索与语义选择 | 本地 LSA 排序后做模板覆盖判断，或在规划中联合完成 | `知识语义匹配_MATCH_PROMPT.txt`、`联合知识判定_JOINT_PROMPT.txt` |
| 证据、适用范围、权限和工单确认 | 后端确定性检查，`validate_decision`、Golden 独占加载器、`PropertyActions`、可信 UI 确认 | 见源码 |
| 自然回复生成 | 需要自然组装时调用 `compose_property_reply`，模板直接返回授权答复 | `回复生成_REPLY_PROMPT.txt` |

对照 Enact 的意图或槽位阶段时，引用同一份语义规划原文。文件 `实际system_普通规划.txt` 与 `实际system_联合知识规划.txt` 是默认在线设置下程序真正拼出的 system 消息，包含由源码追加的紧凑 JSON 说明。联合版本根据原程序将匹配指令改成在 `template_selections` 中输出。请按使用场景选择完整文件，避免把片段再次叠加到已经拼好的 system 消息。

状态、当前用户问题及模板目录由运行程序动态提供。相关工具协议和参数在 `../03_模型与参数/`。
